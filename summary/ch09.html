9장 페이징 메모리

메모리를 같은 크기(페이지)로 나눠 쓰는 방법과 주소 변환

논리 주소→ <P, D>로 나누기 →페이지 테이블에서 P → F→물리 주소 <F, D>

1. 페이징 vs 세그먼테이션

페이징세그먼테이션
나누는 단위같은 크기(페이지 = 논리, 프레임 = 물리)크기가 다른 논리적 단위(세그먼트: 코드, 데이터 등)
기반고정 분할가변 분할
논리 주소<P, D><S, D>
단편화내부 단편화(적음)외부 단편화

페이징이 단순하고 하드웨어 구현이 쉬워서 현재 대부분 OS는 페이징을 사용.

2. 페이지 테이블

  • 페이지 테이블의 한 행 = PTE(Page Table Entry). 페이지 테이블은 프로세스마다 하나, 시작 주소는 PTBR에 저장.
  • 페이지 테이블 행 수 = 최대 프로세스 크기 ÷ 페이지 크기.
  • 쓰기 시점 복사: fork()로 만든 자식은 처음엔 부모와 프레임을 공유하다가, 쓰기가 일어날 때 그 프레임만 복사.

3. 페이지 매핑 방식 4가지

방식설명
직접 매핑페이지 테이블 전체를 메모리에 두고 바로 변환
연관 매핑페이지 테이블 일부를 TLB(변환 색인 버퍼)에 캐시. TLB에 있으면 적중(빠름), 없으면 미스 → 메모리의 테이블 확인
역 매핑물리 메모리의 프레임을 기준으로 테이블 하나만 만듦(테이블 작음, 변환 느림)
다단계 매핑테이블을 나눠 상위 테이블이 관리, 주소가 <P1, P2, D>처럼 여러 단계
  • 지역성: 기억 장치에 접근하는 패턴이 한쪽에 몰리는 성질. 공간 지역성(근처 데이터에 또 접근), 시간 지역성(최근 쓴 데이터를 또 씀), 순차 지역성(순서대로 접근). TLB가 잘 맞는 이유.

4. 세그먼테이션

  • 세그먼테이션 매핑 테이블 = 시작 주소 + 제한 크기(세그먼트 크기).
  • D가 제한 크기보다 크면 → 트랩(영역을 벗어난 인터럽트) → 프로세스 강제 종료, 세그먼테이션 오류 메시지.
🧮 계산 1: 페이징 주소 변환 (가장 많이 나옴!)
  1. P(페이지 번호) = 논리 주소 ÷ 페이지 크기의 몫
  2. D(거리, offset) = 논리 주소 ÷ 페이지 크기의 나머지
  3. 페이지 테이블에서 P번 행을 보고 F(프레임 번호)를 찾음
  4. 물리 주소 = F × 페이지 크기 + D (또는 <F, D>로 표현)

교재 연습문제 표 (페이지 크기 10B)

페이지01234
프레임23410
  • 논리 19번지: 19 ÷ 10 → P 1, D 9 → 페이지 1은 프레임 3 → 3×10 + 9 = 39번지
  • 논리 43번지: P 4, D 3 → 프레임 0 → 0×10 + 3 = 3번지
  • 논리 42번지를 <F, D>로: P 4 → F 0, D 2 → <0, 2> (<4, 2>는 변환 전 <P, D>라서 함정)
  • 페이지 크기가 2의 거듭제곱일 때: 29 = 512 → 2049 ÷ 512 = 몫 4, 나머지 1 → <4, 1>
🧮 계산 2: 페이지 테이블 크기 · 세그먼테이션
  • 행 수 = 2시스템 비트 ÷ 페이지 크기 → 지수끼리는 빼기
    예) 16비트, 페이지 210B → 216 ÷ 210 = 26 = 64행
    예) 32비트, 페이지 4KB(212) → 232−12 = 220행
  • 세그먼테이션: ① D < 제한 크기인지 확인 → ② 물리 주소 = 시작 주소 + D
    예) 세그먼트 2 (시작 630, 제한 170), LA = <2, 80> → 80 < 170 OK → 630 + 80 = 710번지
    LA = <2, 200> → 200 > 170 → 트랩
★ 시험 포인트
  • P = 몫, D = 나머지, 물리 주소 계산 (표 보고 변환)
  • PTE, TLB(연관 매핑), 역 매핑 = 프레임 기준, 다단계 = <P1, P2, D>
  • 쓰기 시점 복사, 공간 지역성, 세그먼테이션 트랩
