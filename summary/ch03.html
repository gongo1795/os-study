3장 프로세스

실행 중인 프로그램(프로세스)을 운영체제가 어떻게 관리하는지

프로그램(파일)→ 메모리에 올라옴 →프로세스→PCB로 관리→상태가 바뀌며 실행

1. 프로그램 vs 프로세스

  • 프로그램: 저장장치에 있는 정적인 파일. 프로세스: 메모리에 적재되어 실행 중인 동적인 상태.
  • PCB(프로세스 제어 블록) = 프로세스 정보 카드. 프로세스 번호(PID), 상태, 우선순위, 프로그램 카운터(어디까지 했나), 메모리 정보 등. OS가 커널 영역에 보관.

2. 프로세스 상태 (그림으로 외우기)

생성→준비⇄실행→완료
실행→ 입출력 요청 →대기→ 입출력 끝 →준비
  • 준비 → 실행: CPU를 받음(디스패치). 실행 → 준비: 타임아웃(타임 슬라이스를 다 씀).
  • 실행 → 대기: 입출력 요청. 대기 → 준비(바로 실행 아님!): 입출력 완료 인터럽트.
  • 활성 상태 = 생성·준비·실행·대기·완료. 휴식(메모리에 있지만 잠깐 멈춤) vs 보류(메모리 밖 스왑 영역으로 쫓겨남).

3. 문맥 교환

문맥 교환 = CPU를 쓰는 프로세스를 바꿀 때, 지금 프로세스의 상태를 PCB에 저장하고 다음 프로세스의 PCB를 불러오는 것.

교환하는 동안엔 실제 일을 못 함(오버헤드). → 타임 슬라이스를 너무 작게 하면 문맥 교환이 많아져 손해. 타임 슬라이스 크기는 문맥 교환 오버헤드를 기준으로 정함.

4. 프로세스의 메모리 구조

영역들어가는 것
코드프로그램 본문(기계어)
데이터전역 변수·정적 변수
힙malloc()으로 빌리고 free()로 돌려주는 동적 공간
스택지역 변수, 함수 호출 후 돌아갈 주소

5. 프로세스 만들기: fork()와 exec()

  • fork(): 나를 복사해서 자식 프로세스를 만듦. 반환값 → 자식에게 0, 부모에게 자식 PID(양수), 실패 시 -1.
  • PID(내 번호), PPID(부모 번호), CPID(자식 번호). 부모의 CPID = 자식의 PID, 새로 만든 자식의 CPID = -1(자식이 없음).
  • exec(): 껍데기(PID·PCB)는 그대로, 안의 코드만 다른 프로그램으로 교체.
  • exit(): 자식이 부모에게 "나 끝났어" 알림. wait(): 부모가 자식이 끝날 때까지 기다림.
  • 유닉스의 모든 프로세스 조상 = init(PID 1). 나머지는 init에서 fork()로 생김.
  • 고아 프로세스: 부모가 먼저 끝남(init이 입양). 좀비 프로세스: 자식은 끝났는데 부모가 모름. 둘 다 exit()/wait()로 방지.
★ 시험 포인트
  • 상태 전이: 입출력 요청 → 대기, 입출력 끝 → 준비, 타임아웃 → 준비
  • fork() 반환값(자식 0), CPID(새 자식 -1), 모든 프로세스의 조상 = init
  • 좀비(부모가 모름) vs 고아(부모가 먼저 끝남), 보류 vs 휴식
  • 힙 = malloc/free, 스택 = 함수 호출·복귀 주소
