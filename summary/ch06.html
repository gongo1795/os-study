6장 임계구역과 동기화

여러 스레드가 공유 자원을 동시에 건드릴 때 생기는 문제와 해결 도구

공유 자원→ 동시 접근 →경쟁 상태→임계구역 보호(잠금)→뮤텍스·스핀락·세마포어·모니터

1. 핵심 용어

  • 경쟁 상태: 2개 이상의 스레드가 공유 자원에 접근하는 순서에 따라 결과가 달라지는 상황. (예: 잔액 10만 원에 두 스레드가 동시에 10만 원씩 입금 → 둘 다 10만을 읽고 20만을 저장 → 30만이 아니라 20만)
  • 임계구역: 공유 자원 중 둘 이상이 동시에 접근하면 안 되는 영역.
  • 동기화: 임계구역에 들어가는 순서를 정리. 쓰고 난 뒤 다음 스레드에게 "써도 돼"라고 알리는 것도 동기화.

2. 임계구역 보호의 3가지 조건 + 위반 코드

조건뜻위반하는 코드 (외우기!)
상호 배제한 번에 1개만 들어감while(lock==true); lock=true; → 검사 후 잠그기 전에 끊기면 둘 다 들어감
한정 대기무한히 기다리는 스레드가 없어야 함lock1=true; while(lock2==true); → 둘 다 깃발을 들면 서로 영원히 기다림
진행의 융통성다른 스레드의 진행을 방해하면 안 됨while(lock==2); … lock=2; → 무조건 번갈아서만 들어감(경직된 동기화)

검사와 지정(test_and_set): 검사와 잠금을 하드웨어가 원자적으로 한 번에 실행 → 상호 배제 해결. 단, 고수준 언어(C·자바)에서 쓰기 어려움.

3. 동기화 도구

도구특징
뮤텍스공유 자원 1개. lock/unlock. 잠겨 있으면 잠들어서 기다림(바쁜 대기 X)
스핀락잠겨 있으면 CPU를 쓰며 계속 확인 = 바쁜 대기
세마포어공유 자원 여러 개. init(n) → wait() → [임계구역] → post()
모니터lock/unlock을 자동으로 처리. 자바의 synchronized
  • 세마포어 S = 남은 자원 수. wait(): if S <= 0 then pause() (자원 없으면 대기) → 아니면 S−1 하고 들어감. post(): S+1 하고 기다리던 스레드를 깨움.
  • 공유 자원 2개, 스레드 3개 → init(2) (스레드 수가 아님!). 자원 1개면 init(1) = 이진 세마포어.
  • 세마포어 코드 순서 = wait() → post().

4. 우선순위 역전

우선순위 역전: 임계구역 때문에 우선순위가 높은 스레드가 낮은 스레드보다 늦게 끝나는 현상. (낮은 T9가 임계구역 사용 중 → 높은 T1이 기다림 → 중간 T5가 T9의 CPU를 뺏음 → T1이 가장 늦게 끝남)

  • 우선순위 상속: 임계구역을 쓰는 낮은 스레드에게 높은 우선순위를 잠깐 물려줌.
  • 우선순위 상한: 임계구역을 쓰는 모든 스레드의 우선순위를 일정 수준까지 올림.
★ 시험 포인트
  • 코드 보고 어떤 조건을 위반하는지 고르기 (위 표 3줄)
  • 뮤텍스(1개) vs 세마포어(여러 개) vs 모니터(자동, synchronized), 스핀락 = 바쁜 대기
  • wait() 첫 줄 = if S <= 0 then pause(), 자원 2개 → init(2)
  • 상속 vs 상한 구분

6장에는 숫자 계산 문제가 없어서 계산 박스는 없어요. 대신 "코드 → 위반 조건" 찾기가 계산처럼 자주 나와요.
