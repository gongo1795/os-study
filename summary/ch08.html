8장 메모리와 할당

메모리 주소, 메모리 보호, 컴파일, 그리고 메모리를 프로세스에 나눠 주는 방법

메모리 구조·주소→보호(경계·한계 레지스터)→논리 주소 → 물리 주소→가변 분할 / 고정 분할

1. 메모리의 기본

  • 저장장치 계층구조 맨 위(가장 빠름) = 레지스터 → 캐시 → 메모리 → 저장장치.
  • 메모리 주소는 1바이트마다 하나씩. 32비트 CPU → 주소 232개(4GB), 주소 범위 0 ~ 232 − 1.
  • 커널을 높은 주소에 배치: 사용자 영역과 멀어져 침범이 어렵고(보안), 사용자 영역이 0번지부터 시작해 매핑이 단순해짐.

2. 메모리 보호

  • 경계 레지스터 = 프로세스의 시작 주소, 한계 레지스터 = 프로세스의 마지막 주소.
  • 프로세스가 이 범위를 벗어나는지 하드웨어가 검사 → 벗어나면 강제 종료.

3. 컴파일과 라이브러리

소스 코드→ 컴파일(오류 점검·번역) →목적 코드→ 연결(링크) →실행 파일
  • 목적 코드: 기계어로 번역됐지만 라이브러리 함수의 기계어가 아직 없는 중간 결과물.
  • printf() 같은 라이브러리 코드는 연결 단계에서 들어감.
  • 헤더 포함: 시스템 라이브러리 <stdio.h>, 사용자 라이브러리 "myfile.h"(쌍따옴표).
  • 정적 라이브러리(실행 파일에 넣음) vs 동적 라이브러리(실행할 때 불러옴, DLL) → 현대 OS는 동적.

4. 논리 주소와 물리 주소

  • 논리 주소: 프로세스 입장의 주소, 항상 0번지부터. 물리 주소: 실제 메모리 주소.
  • MMU(메모리 관리 유닛)가 변환: 물리 주소 = 재배치(경계) 레지스터의 시작 주소 + 논리 주소.
  • 메모리 오버레이: 물리 메모리보다 큰 프로그램을 잘라서 필요한 부분만 올리고 같은 자리에 덮어씀.
  • 스왑 영역: 메모리가 모자랄 때 데이터를 잠시 옮기는 곳. 저장장치에 있지만 메모리 관리자가 관리. (스왑 아웃: 메모리 → 스왑, 스왑 인: 스왑 → 메모리)

5. 메모리 분할 방식

가변 분할 (연속 할당)고정 분할 (비연속 할당)
방식프로세스 크기에 맞게 나눔같은 크기로 나눔
장점프로세스를 한 덩어리로 관리메모리 관리가 편리
단점빈 공간 관리가 어려움프로세스가 쪼개져 처리됨
단편화외부 단편화(프로세스 사이 빈 조각)내부 단편화(한 칸 안에 남는 공간)
  • 가변 분할 배치 전략: 최초 배치(앞에서부터 처음 맞는 빈 공간), 최적 배치(가장 비슷한 크기, 아주 작은 조각이 생김), 최악 배치(가장 큰 빈 공간, 남은 공간을 다시 쓸 수 있음).
  • 조각 모음: 흩어진 빈 공간을 하나로 합침(외부 단편화 해결, 프로세스를 멈추고 옮겨야 함).
  • 버디 시스템: 프로세스가 들어가는 최소 크기가 될 때까지 메모리를 1/2씩 자름 → 끝나면 짝(버디)끼리 합침. 비슷한 크기 조각이 모여 있어 합치기 쉬움.
🧮 계산: 주소 변환과 단편화
  • 물리 주소 = 시작 주소 + 논리 주소
    예) 시작 124번지, 논리 74번지 → 124 + 74 = 198번지
  • n비트 시스템의 마지막 주소 = 2n − 1 (0부터 세니까)
    예) 32비트 → 232 − 1
  • 내부 단편화 = 칸 크기 − 프로세스 크기
    예) 10KB 칸에 8KB 프로세스 → 2KB 낭비
  • 버디 시스템: 반으로 자르기를 반복해 프로세스가 들어가는 가장 작은 2의 거듭제곱 블록에 넣기
    예) 16B 메모리, 3B 프로세스 → 16 → 8 → 4B 블록 (2B로 자르면 안 들어감), 1B는 단편화
★ 시험 포인트
  • 경계 = 시작 주소, 한계 = 마지막 주소 (크기 아님!)
  • 목적 코드, 연결 단계, DLL = 동적 라이브러리
  • 논리 주소는 0번지부터, 스왑 영역은 메모리 관리자가 관리, 오버레이
  • 가변 = 외부 단편화, 고정 = 내부 단편화, 조각 모음, 배치 전략 3가지
근거: 수업 교재 8장 본문·장 끝 요약·연습문제, 연습문제 해답(홀수). 형광펜 = 꼭 외울 것, 주황 상자 = 계산, 점선 상자 = 시험 포인트.
