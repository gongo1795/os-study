2장 컴퓨터의 구조와 성능 향상

CPU·메모리·버스의 구조와, 느린 장치 때문에 생기는 손해를 줄이는 기술

CPU는 빠르고/메모리·저장장치·입출력은 느림→그 차이를 메우는 기술 모음

1. 컴퓨터의 기본 구성

요리사 모형: 요리사 = CPU, 조리대 = 메모리, 창고 = 저장장치(하드디스크·SSD). 요리는 조리대 위에서만 → CPU는 메모리에 올라온 것만 처리.

  • 메인보드 = CPU·메모리 등 부품을 연결하고 전원을 공급하는 기판.
  • 폰노이만 구조: 모든 프로그램은 메모리에 올라와야 실행된다.

2. CPU 안쪽

  • CPU = 산술논리 연산장치(ALU)(계산) + 제어장치(지휘) + 레지스터(CPU 안의 초고속 메모장).
레지스터저장하는 것
PC (프로그램 카운터)다음에 실행할 명령어 주소 ("현재"가 아님!)
IR (명령어 레지스터)지금 실행 중인 명령어
MAR (메모리 주소 레지스터)읽고 쓸 메모리 주소
MBR (메모리 버퍼 레지스터)메모리에서 가져오거나 보낼 데이터
상태(PSR)·플래그·조건 레지스터연산 결과(양수/음수/0 등). 셋 다 같은 것의 다른 이름
  • 버스: 제어 버스(제어 신호, 양방향) / 주소 버스(메모리 주소, 단방향, MAR과 연결) / 데이터 버스(데이터, 양방향, MBR과 연결).
  • CPU–메모리를 잇는 시스템 버스 = FSB(전면 버스), CPU–캐시 = BSB(후면 버스).
  • 32비트 CPU = 레지스터(MAR·MBR) 크기와 버스 대역폭이 32비트로 같음. 메모리 한 칸(주소 1개 = 1바이트)은 크기가 다름.

3. 부팅

전원 ON → ROM의 BIOS가 하드웨어 점검 → 디스크 맨 앞 MBR(마스터 부트 레코드)의 부트스트랩 코드 실행 → 운영체제를 메모리에 올림.

4. 성능 향상 기술 (속도 차이 메우기)

  • 버퍼: 속도 차이를 메우는 임시 저장 공간. 스풀: 소프트웨어 버퍼(프린터 대기열, 한 번에 한 문서).
  • 캐시: 앞으로 쓸 데이터를 미리 가져다 둔 곳. 있으면 캐시 적중(hit), 없으면 캐시 미스(miss).
  • 저장장치 계층구조: 빠르고 작은 것(레지스터·캐시) ~ 느리고 큰 것(하드디스크)을 층층이 → 싸게 빠르고 크게. 단점: 같은 데이터가 여러 층에 있어 일관성 유지가 어려움.
  • 인터럽트: CPU는 자기 일을 하고, 입출력이 끝나면 장치가 신호로 알려 줌. (반대: 폴링 = CPU가 계속 "끝났어?" 확인 → 낭비)
  • DMA(직접 메모리 접근): CPU 허락 없이 입출력 장치가 메모리에 직접 접근. MMIO(메모리 매핑 입출력): 메모리 일부를 입출력용으로 할당.
  • 사이클 훔치기: CPU와 DMA가 동시에 메모리를 쓰려 할 때 입출력 장치(DMA) 쪽에 양보.
  • 병렬 처리: 파이프라인(명령을 겹쳐 실행), 슈퍼스칼라(파이프라인 여러 개). 멀티프로세서(CPU 여러 개) vs 멀티코어(한 CPU 칩 안에 코어 여러 개).
★ 시험 포인트
  • PC = 다음 명령어 주소 (현재 X), MAR = 주소 / MBR = 데이터
  • 단방향 버스 = 주소 버스, 버스–레지스터–데이터 짝짓기
  • 저장장치 계층구조의 단점 = 일관성 유지, 미리 가져오는 곳 = 캐시
  • CPU 허락 없이 메모리 접근 = DMA, 메모리 일부를 입출력에 할당 = MMIO
근거: 수업 교재 2장 본문·장 끝 요약·연습문제, 연습문제 해답(홀수). 형광펜 = 꼭 외울 것, 주황 상자 = 계산, 점선 상자 = 시험 포인트.
