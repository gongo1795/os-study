10장 가상 메모리 관리

물리 메모리보다 큰 주소 공간을 쓰는 방법, 페이지 교체 알고리즘, 스레싱

요구 페이징→페이지 부재→페이지 교체 알고리즘→ 너무 잦으면 →스레싱→프레임 할당

1. 가상 메모리

  • 가상 메모리: 물리 메모리 크기와 상관없이 큰 논리 주소 공간을 제공. 가상 메모리 크기 = 물리 메모리 + 스왑 영역.
  • 요구 페이징: 필요한 페이지만 메모리에 올리고, 나머지는 요청할 때 가져옴.
  • 페이지 부재(page fault): 요청한 페이지가 메모리에 없음 → 스왑 영역에서 가져옴(메모리가 꽉 찼으면 하나를 내보냄 = 대상 페이지).
  • 세그먼테이션 오류: 자기 메모리 영역을 벗어난 접근 (페이지 부재와 구분!).
PTE 플래그 비트뜻
접근(참조) 비트페이지에 접근(읽기·실행)한 적이 있으면 1
변경(더티) 비트페이지 내용을 바꾼(쓰기) 적이 있으면 1
유효(현재) 비트교재 기준 0 = 메모리에 있음, 1 = 스왑 영역에 있음
읽기·쓰기·실행 비트해당 권한

2. 페이지 교체 알고리즘

교체할 페이지는 지역성(앞으로 덜 쓸 것)을 근거로 골라요.

알고리즘내보내는 페이지특징
무작위아무거나지역성 무시, 성능 나쁨
FIFO메모리에 가장 먼저 들어온 것단순, 성능 가장 낮음(자주 쓰는 것도 쫓아냄)
최적(OPT)앞으로 가장 늦게 쓰일 것성능 최고지만 미래를 알 수 없어 구현 불가
LRU마지막 사용 시각이 가장 오래된 것접근 시각·카운터·참조 비트 시프트로 구현, 추가 메모리 필요
LFU사용 횟수가 가장 적은 것횟수를 기록할 추가 메모리 필요
NUR(접근, 변경) 비트로 판단LRU·LFU와 성능 비슷 + 공간 낭비 해결
2차 기회FIFO인데 성공한 페이지는 큐 맨 뒤로FIFO보다 조금 좋음
시계원형 큐 + 대상 포인터, 접근 비트 사용접근 비트 1이면 0으로 바꾸고 한 번 더 기회

최적 근접 알고리즘 = LRU·LFU·NUR (과거를 보고 미래를 예측). FIFO 변형 = 2차 기회·시계.

3. 스레싱과 프레임 할당

  • 스레싱: 멀티프로그래밍 수준이 너무 높아 페이지 부재가 너무 많고, 페이지 교체(스왑 입출력)만 하느라 작업이 멈춘 것 같은 상태.
  • 정적 할당: 처음에 정함 → 균등 할당(모두 똑같이), 비례 할당(프로세스 크기에 비례).
  • 동적 할당: 실행 중 조절 → 작업 집합 모델(최근 일정 시간 동안 참조된 페이지 묶음을 메모리에 유지), 페이지 부재 빈도(부재율이 높으면 프레임 추가, 낮으면 회수).
  • 교체 범위: 지역 교체(자기 프레임 안에서만 교체) vs 전역 교체(전체 프레임에서 교체).

  • FIFO 4번(D): 가장 먼저 온 A 아웃 / OPT 4번(D): A는 6번, B는 5번, C는 9번에 다시 쓰임 → 가장 늦은 C 아웃
  • LRU 6번(A): 마지막 사용 시각 B 5, C 3, D 4 → 가장 오래된 C 아웃
  • LFU: 사용 횟수가 같으면 위쪽(먼저 있던 자리) 페이지 아웃 → 6번에서 D 아웃, 이후 전부 성공
🧮 계산 2: NUR 순서 · 참조 비트 시프트
  • NUR (접근 비트, 변경 비트) 내보내는 순서: (0,0) → (0,1) → (1,0) → (1,1)
    접근 비트를 먼저 봄. 첫 번째 = (0,0), 두 번째 = (0,1), 세 번째 = (1,0).
  • LRU 참조 비트 시프트: 일정 시간마다 모든 비트를 오른쪽으로 1칸 밀고, 접근한 페이지는 맨 앞자리를 1로. → 비트를 2진수로 읽어 가장 작은 값 = 가장 오래 안 쓴 페이지 = 대상.
    예) 00111011, 10000000, 01000001, 11100000 중 → 00111011 (교재 연습문제 21번) (1이 많아도 맨 앞이 작으면 작음! LFU와 헷갈리지 않기)
★ 시험 포인트
  • 가상 메모리 = 물리 + 스왑, 페이지 부재 vs 세그먼테이션 오류
  • FIFO / OPT / LRU / LFU 손으로 따라가기, 성능 가장 낮은 것 = FIFO
  • NUR 순서, 시계 = 접근 비트, LFU는 추가 메모리 필요
  • 스레싱, 작업 집합 모델, 페이지 부재 빈도 = 동적 할당
