4장 스레드와 프로세스 간 통신

프로세스 안의 일꾼(스레드)과, 프로세스끼리 데이터를 주고받는 방법(IPC)

※ 4장 175~187쪽(포트·소켓·심화 코드 부분)은 시험 범위에서 빠져서 요약에도 넣지 않았어요.

프로세스 = 그릇→스레드 = 그 안의 일꾼/프로세스끼리 통신 = IPC

1. 스레드

  • 작업 단위 크기: 작업(job) > 프로세스 > 스레드. 작업 = 사용자가 맡긴 일 전체, 스레드 = CPU가 실제로 실행하는 가장 작은 일 단위(경량 프로세스).
  • 멀티스레드: 한 프로세스 안에 스레드 여러 개. 코드·데이터·힙·파일은 공유, 레지스터·스택만 각자.
  • 멀티태스크(프로세스 여러 개): 서로 독립 → 안정적이지만 자원을 복사해서 낭비.
멀티스레드 장점
  • 응답성 향상(하나가 멈춰도 다른 스레드가 반응)
  • 자원 공유가 쉬움
  • 효율성(복사 X, 통신 오버헤드 적음)
  • 멀티 CPU·멀티코어 활용
멀티스레드 단점
  • 한 스레드에 문제가 생기면 프로세스 전체에 영향
  • "스레드끼리 독립적" = 틀림 (그건 프로세스)

스레드 모델: 사용자 레벨(1 to N), 커널 레벨(1 to 1), 멀티레벨(M to N) = 둘을 섞음. (비중 낮음)

2. 프로세스 간 통신 (IPC)

프로세스끼리는 메모리가 막혀 있어서 데이터를 건넬 방법이 따로 필요해요.

비동기화 통신동기화 통신
기다리는 방법내가 계속 확인 = 바쁜 대기OS가 재워 두고 오면 깨워 줌 = 블로킹
예공유 메모리, 파일파이프, 소켓
  • 요령: "OS가 기다려 주면 동기화, 내가 확인하면 비동기화."
  • 통신 방향: 단방향(한쪽으로만) / 양방향 / 반양방향(무전기처럼 번갈아).
  • 파이프: 같은 컴퓨터 안, 단방향 관. 양방향이 필요하면 파이프 2개. 기술자 fd[0] = 읽기, fd[1] = 쓰기.
  • 소켓: 다른 컴퓨터와 통신, 양방향. (자세한 소켓 코드는 범위 밖)
  • 스레드 함수 ↔ 프로세스 함수: create ↔ fork, join ↔ wait, exit ↔ exit.
★ 시험 포인트
  • 가장 큰 작업 단위 = 작업(job), 스레드끼리 공유하는 것 vs 각자 갖는 것
  • 멀티스레드 장점이 아닌 것 = "스레드끼리 독립적"
  • 바쁜 대기를 쓰는 통신 = 공유 메모리, 비동기화의 특징이 아닌 것 = 블로킹
